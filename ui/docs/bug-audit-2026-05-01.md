# Vue UI Bug Audit — 2026-05-01

27 bugs found by sweeping all page containers and common components.
Organised by severity. Check off each item as it lands.

---

## Critical — breaks visible features or causes runtime crashes

- [ ] **C1 · Map.vue — calls getters instead of fetchers, map always empty**
  - File: `ui/src/containers/Map.vue`
  - `mapStore.getNodes()` / `mapStore.getAlarms()` are getter accessors, not async fetchers.
    The map mounts, calls them immediately, gets empty arrays, and never re-tries.
  - Fix: call the correct fetch actions (e.g. `fetchNodes()` / `fetchAlarms()`) in `onMounted`.

- [ ] **C2 · router/index.ts — `/event-config/create` shadowed by `/:id` route**
  - File: `ui/src/router/index.ts`
  - `/event-config/create` is registered *after* `/event-config/:id`, so navigating to
    `/event-config/create` loads the detail view with `id = "create"`.
  - Fix: move the `create` route above the `:id` wildcard.

- [ ] **C3 · EventConfigurationDetail.vue — "not found" flash before fetch resolves**
  - File: `ui/src/containers/EventConfigurationDetail.vue`
  - `v-else>No event configuration found` (with a "Go Back" button) renders while the
    initial fetch is still in-flight.
  - Fix: add the standard `!store.isLoading &&` guard, same pattern applied to
    `EventConfigEventTable`, `NodesTable`, and `ConfigurationTableWrapper` this session.

- [ ] **C4 · OutageDetail.vue — spinner sticks on any API error**
  - File: `ui/src/containers/OutageDetail.vue`
  - `loading.value = false` is only in the `.then()` path; a thrown error leaves the page
    in a permanent loading state.
  - Fix: move `loading.value = false` into a `finally` block.

- [ ] **C5 · Pagination.vue — unmount/remount triggers duplicate fetch loop**
  - File: `ui/src/components/Common/Pagination.vue`
  - The Paginator is wrapped in `v-if="totalCount"`. When an in-flight filter clears
    results, `totalCount` goes to 0, the Paginator unmounts, then the parent re-mounts
    it and triggers another fetch, which can reset `totalCount` again — an oscillation loop.
  - Fix: keep the Paginator mounted (`v-show` or always-render) regardless of count.

- [ ] **C6 · Plugin.vue — CSS `<link>` tags accumulate across navigations**
  - File: `ui/src/containers/Plugin.vue`
  - Each plugin navigation appends a new `<link>` to `<head>` without removing the
    previous one. After visiting several plugins the document carries all their stylesheets
    simultaneously, causing style conflicts.
  - Fix: track injected `<link>` refs and remove them in `onBeforeUnmount` / before the
    next stylesheet is inserted.

## Important — data loss, stuck states, or incorrect behaviour under realistic conditions

- [ ] **I7 · Events.vue — no `finally` + raw FIQL injection from search input**
  - File: `ui/src/containers/Events.vue`
  - (a) Like C4, missing `finally` means the events spinner sticks on any API error.
  - (b) The search string is concatenated directly into the FIQL query. Commas, `==`, and
    other FIQL operators in user input break or hijack the query.
  - Fix: (a) wrap fetch in try/finally; (b) escape/encode the search term before
    interpolating it into the FIQL expression.

- [ ] **I8 · InterfaceDetail.vue — Services tab spinner sticks forever on error**
  - File: `ui/src/containers/InterfaceDetail.vue`
  - Services fetch uses `.then()` only — no `.catch()` or `.finally()`. Any API error
    leaves the spinner spinning indefinitely.
  - Fix: add `.finally(() => { loading.value = false })`.

- [ ] **I9 · FlowClassification.vue — rules table spinner sticks on error**
  - File: `ui/src/containers/FlowClassification.vue`
  - Same missing-`finally` pattern as I8.
  - Fix: same — add `finally` block around the rules fetch.

- [ ] **I10 · nodeStore.ts — `node` initialised as `{} as Node`, causes null-deref**
  - File: `ui/src/stores/nodeStore.ts`
  - `node = ref({} as Node)` — consumers that access `node.assetRecord.latitude` (etc.)
    without optional-chaining will throw on the initial render before the API responds.
  - Fix: initialise as `ref<Node | null>(null)` and update all callers to use `node.value?.`.

- [ ] **I11 · menuStore.ts — `mainMenu` initialised as `{} as MainMenu`**
  - File: `ui/src/stores/menuStore.ts`
  - `homeUrl` is `undefined` until the menu API responds. The Home breadcrumb link
    renders as `href="undefined"` on the first paint, linking to the current page.
  - Fix: same approach as I10 — `ref<MainMenu | null>(null)` with null-safe consumers.

- [ ] **I12 · SurveillanceDashboard.vue — stale auto-refresh timer races new fetch**
  - File: `ui/src/containers/SurveillanceDashboard.vue`
  - When the view changes the old `setInterval` is not cleared before a new one starts.
    Both timers fire simultaneously, producing duplicate requests and potential race
    conditions overwriting reactive state.
  - Fix: clear the previous interval in the route-change or filter-change handler before
    starting the next one; also clear in `onBeforeUnmount`.

- [ ] **I13 · DestinationPathEdit.vue — `v-for` keyed by index on a deletable list**
  - File: `ui/src/containers/DestinationPathEdit.vue`
  - Targets and escalations use `:key="index"`. When an item is deleted, Vue reuses the
    existing DOM nodes by index, causing focused inputs to jump to the wrong row.
  - Fix: key by a stable ID (e.g. the target's name or a generated UUID).

- [ ] **I14 · NodeDetails.vue — `activeTab` watcher fires during `onMounted` assignment**
  - File: `ui/src/containers/NodeDetails.vue`
  - Setting `activeTab` in `onMounted` triggers the watcher immediately, producing a
    redundant `router.replace` that can race the real initial navigation.
  - Fix: use `{ immediate: false }` on the watcher, or guard with a mounted flag.

- [ ] **I15 · Map.vue — debounced `invalidateSizeFn` crashes on unmounted component**
  - File: `ui/src/containers/Map.vue`
  - `leafletComponent.value.invalidateSizeFn()` is called inside a 200 ms debounce.
    If the user navigates away within that window, `leafletComponent.value` is null and
    the call throws.
  - Fix: cancel the debounce timer in `onBeforeUnmount`, or null-check before calling.

- [ ] **I16 · DiscoveryConfig.vue — one `Promise.all` failure leaves page stuck loading**
  - File: `ui/src/containers/DiscoveryConfig.vue`
  - `Promise.all([getDiscoveryConfig(), getLocations(), getForeignSources()])` — if any
    one promise rejects the others' results are discarded and the page stays in the
    loading state with no error feedback.
  - Fix: use `Promise.allSettled` and surface the partial error; or at minimum add a
    `.catch` that clears the loading flag and shows a toast.

- [ ] **I17 · Plugin.vue — shallow `props` watcher misses same-`moduleFileName` changes**
  - File: `ui/src/containers/Plugin.vue`
  - The plugin reload watcher observes the whole `props` proxy shallowly. When navigating
    between two plugins that happen to share the same `moduleFileName` but differ only in
    `extensionId`, the shallow comparison sees no change and the plugin is not reloaded.
  - Fix: watch `() => props.extensionId` (and/or `props.moduleFileName`) explicitly.

- [ ] **I18 · Logs.vue — `.filter()` on `undefined` crashes the entire page**
  - File: `ui/src/containers/Logs.vue`
  - If `getLogs()` returns `undefined` (e.g. on API error), calling `.filter()` on it
    throws a TypeError that takes down the whole page.
  - Fix: default to an empty array: `(await getLogs()) ?? []`.

## Minor — low-impact or edge-case issues

- [ ] **M19 · SystemConfig.vue — "Client Time" is a page-load snapshot, never updates**
  - File: `ui/src/containers/SystemConfig.vue`
  - The displayed client timestamp is captured once at mount. On long-lived sessions it
    drifts from the actual current time.
  - Fix: either refresh on an interval or remove the field if it adds no value.

- [ ] **M20 · DeleteNodes.vue — debounce timer not cleared on unmount**
  - File: `ui/src/containers/DeleteNodes.vue`
  - The search debounce fires `load()` against a component that may have been destroyed,
    producing a harmless-but-noisy console error and a wasted network request.
  - Fix: cancel the debounce in `onBeforeUnmount`.

- [ ] **M21 · WallboardConfig.vue — `selectedIndex` can go negative after last item deleted**
  - File: `ui/src/containers/WallboardConfig.vue`
  - Deleting the last wallboard board decrements `selectedIndex` to `-1`, leaving the
    UI with nothing selected and no empty-state fallback.
  - Fix: clamp to `Math.max(0, list.length - 1)` after deletion, and show an empty state
    when the list is empty.

- [ ] **M22 · BreadCrumbs.vue — `:key="item.label"` collides on duplicate labels**
  - File: `ui/src/components/Layout/BreadCrumbs.vue`
  - Duplicate breadcrumb labels (possible in some nested admin paths) produce duplicate
    Vue keys, causing rendering artefacts.
  - Fix: key by index, or by a combination of index + label.

- [ ] **M23 · EmptyList.vue — button renders with no accessible name**
  - File: `ui/src/components/Common/EmptyList.vue`
  - The action button is rendered without a `label` prop in some call sites, producing a
    button with no text that screen-readers announce as unlabelled.
  - Fix: make `label` required (add a PropType validator), or supply a sensible default.

- [ ] **M24 · Pagination.vue — `pageSize` prop change doesn't trigger a refetch**
  - File: `ui/src/components/Common/Pagination.vue`
  - Changing the page-size selector does not re-emit `update` with the new limit, so the
    data set stays at the old page size until the user manually clicks a page.
  - Fix: watch `pageSize` and emit a page-1 fetch whenever it changes.

- [ ] **M25 · Pagination.vue — `payload` prop silently drops `parameters` on first request**
  - File: `ui/src/components/Common/Pagination.vue`
  - When the `payload` prop is present, the `parameters` limit/orderBy values are not
    merged into the first request, causing the initial fetch to use server defaults.
  - Fix: merge both `payload` and `parameters` before emitting.

- [ ] **M26 · Snackbar.vue — dismiss button not inside `aria-live` region**
  - File: `ui/src/components/Common/Snackbar.vue`
  - The dismiss button is rendered outside the `aria-live` announcement region. Screen
    readers may not associate it with the notification and will not announce it on focus.
  - Fix: move the button inside the `role="alert"` / `aria-live` container.

- [ ] **M27 · PerspectiveToggle.vue — mode tooltip only in `title`, invisible on touch**
  - File: `ui/src/components/Common/PerspectiveToggle.vue`
  - The descriptive text for each perspective mode lives only in the HTML `title`
    attribute, which is not shown on mobile/touch devices.
  - Fix: replace or augment with a PrimeVue `Tooltip` directive so it works everywhere.
